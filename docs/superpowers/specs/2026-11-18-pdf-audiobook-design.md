# PDF → Audiobook (iPhone web app) — Design

Date: 2026-11-18
Status: draft, awaiting owner approval

## 1. Intent and why

The owner wants to listen to PDFs (books, course material, articles) as
audiobooks while driving. The audio must be generated by an AI voice and
played from an app on the owner's iPhone. It is a personal tool: one user,
never published to a store.

Success = the owner can add a PDF from the iPhone, wait for it to convert,
and later listen in the car — offline, resuming where they stopped — with a
natural-sounding Brazilian Portuguese voice, at little or no cost.

## 2. Goals

- Import a PDF (with selectable text) from the iPhone Files app / iCloud / Drive.
- Extract and clean the text so the voice reads only the content.
- Split into chapters (from the PDF outline) or ~10-minute parts.
- Convert each part to MP3 with Google Cloud Text-to-Speech, pt-BR voice.
- Store the audio on the phone so playback needs no internet.
- Player: play/pause, ±30 s, speed 0.75×–2×, per-book resume position,
  chapter list, lock-screen / Now Playing controls where iOS allows.
- Export a chapter's MP3 to Files (fallback for car playback, see §5).
- Settings: Google API key, voice choice (male/female pt-BR).

## 3. Non-goals

- Scanned PDFs / OCR (owner confirmed their PDFs have selectable text).
- Native iOS app, App Store, TestFlight, CarPlay integration.
- Multiple users, accounts, login, sync between devices, a backend server.
- Languages other than pt-BR (keep voice/language a setting, but only pt-BR
  is tested).
- EPUB, DOCX or other input formats.

## 4. Anti-goals (would make it a failure even if it "works")

- Audio that reads page numbers, running headers/footers, or broken
  hyphenated words aloud on every page.
- Losing the listening position or already-converted audio (re-converting
  costs money/quota).
- Any Google bill at all. Owner decided: **never pay** — the app must never
  send characters beyond the monthly free tier (see "Free-tier guard").
- The API key leaking beyond the owner's device and the app's domain.

## 5. Constraints

- **Platform:** iPhone, Safari "Add to Home Screen" web app (PWA). Owner has
  no Mac and chose not to pay the Apple Developer fee, so native is out.
- **Dev machine:** Windows. No Mac-only tooling.
- **Known iOS limitation (accepted by owner):** iOS may pause web-app audio
  when the screen locks or the app is backgrounded, and PWAs do not appear in
  CarPlay. Mitigations: Media Session API for lock-screen controls; MP3
  export via the Web Share API (`navigator.share({ files })` → "Save to
  Files") so the owner can play files from the Files app or another player.
  `<a download>` is unreliable in standalone mode; use share sheet first,
  fall back to download link.
- **iOS suspends JavaScript in the background.** Conversion only progresses
  while the app is in the foreground. Conversion must be resumable per chunk
  and should request a Screen Wake Lock while converting (best effort).
- **Storage:** IndexedDB on the device. Call `navigator.storage.persist()`.
  Home-screen web apps are exempt from Safari's 7-day eviction, but storage
  can still be cleared by the user or by low disk; show used space per book
  and allow deleting a book's audio.
- **Google Cloud TTS:** REST `POST https://texttospeech.googleapis.com/v1/text:synthesize?key=…`
  called directly from the browser. Max 5,000 bytes of input per request →
  the text is synthesized in chunks split on sentence boundaries and the
  returned MP3 segments are concatenated per chapter (MP3 frames concatenate
  safely). `audioEncoding: MP3`.
- **Cost:** owner decided zero cost. Default to a voice tier with a free
  monthly quota (Neural2 or WaveNet pt-BR; builder verifies the current
  free-tier numbers and voice names at build time and stores the limit per
  tier as a constant). Show estimated characters and how much of this
  month's free quota the book will use before converting.
- **Free-tier guard (hard requirement):** the app keeps a per-calendar-month
  counter of characters sent to Google, per voice tier, in IndexedDB. Before
  each chunk request it checks `used + chunkChars <= limit × 0.95` (5 %
  safety margin for counting differences). If not, it does not send; the
  book goes to status "Pausado — cota do mês esgotada, continua em <date>"
  and resumes automatically on the first app open of the next month. Failed
  requests that Google may still have billed count as used. Settings shows
  the month's usage. Single user, single device, single key, so a local
  counter is sufficient; README tells the owner not to reuse the key
  elsewhere and, as a second safety net, to set a Google Cloud budget alert
  and an API quota cap on characters/day if available.
- **API key safety:** key is entered in Settings and stored only in the
  device's IndexedDB/localStorage, never committed. Setup guide tells the
  owner to restrict the key to the Text-to-Speech API and to the app's
  HTTP referrer (GitHub Pages domain).
- **Hosting:** static site on GitHub Pages (HTTPS, free). Needs a web app
  manifest, icons, and a service worker so the app shell opens offline.

## 6. Approaches considered

| Approach | Trade-off | Decision |
|---|---|---|
| Native app built in the cloud (Expo/EAS) + Apple Developer account (US$ 99/yr), installed via TestFlight | Reliable background audio, lock screen, CarPlay; costs US$ 99/yr | Rejected for now (cost) — recommended upgrade path if PWA audio proves too limiting |
| Native app via Xcode + free Apple ID | Free, full native; needs a Mac and reinstall every 7 days | Rejected (no Mac) |
| **Web app on the home screen (PWA)** | Free, buildable from Windows; iOS may pause audio when locked, no CarPlay | **Chosen by owner**, with MP3 export as the car fallback |

Voice provider: Google Cloud TTS chosen by owner (natural pt-BR voices, free
monthly quota). Considered: OpenAI TTS (~US$ 9/book), ElevenLabs (best,
most expensive), Azure Neural (similar to Google).

Keep the TTS call behind a small `ttsProvider` interface so a provider swap
(or a later native app reusing the logic) is cheap.

1. **Library:** list of books with status (converting %, ready, progress),
   "+ Adicionar PDF" (file input `accept="application/pdf"`).
2. **Import review** (after picking a PDF): title (editable, from metadata
   or filename), detected chapters, total characters, estimated audio
   duration, voice; "Converter" button. Lets the user deselect chapters
   (e.g. index, bibliography) to save quota.
3. **Player:** current chapter, scrubber, ±30 s, play/pause, speed,
   chapter list, export MP3.
4. **Settings:** API key (with "Testar" button), voice picker with preview,
   default speed, storage used, link to the key-setup guide.

### Pipeline

1. **Extract:** pdf.js `getTextContent()` per page, keeping each text item's
   y-position.
2. **Clean:**
   - drop lines that repeat at the top/bottom of most pages (running
     headers/footers) and lines that are only a page number;
   - join hyphenated line breaks (`exem-\nplo` → `exemplo`);
   - join lines into paragraphs; collapse whitespace;
   - **two-column pages:** detect by a vertical gap in text x-positions
     around the page middle; read left column then right column;
   - **footnotes:** drop small-font lines at the bottom of the page
     (font size clearly below the page's body size) and footnote markers
     (superscript digits) in body text;
   - tables, captions and URLs: no special handling in v1 (read as text;
     URLs replaced by the word "link").
   Builder's call (owner did not specify their PDF layouts); tune on sample
   PDFs if the owner provides them.
3. **Split into chapters:** use `getOutline()` top-level entries mapped to
   page indices. If no outline, split into parts of ~10 minutes of speech
   (~9,000 characters, cut at paragraph boundaries).
4. **Chunk:** split each chapter into ≤ 5,000-byte (UTF-8) chunks at sentence
   boundaries.
5. **Synthesize:** call Google TTS per chunk sequentially, retry with
   backoff on 429/5xx; persist each chunk's MP3 as soon as it arrives
   (so closing the app loses at most one chunk). Stop and surface a clear
   message on 400/403 (bad key, API not enabled, quota).
6. **Assemble:** when all chunks of a chapter exist, concatenate into one
   chapter MP3 blob and store it; chunk blobs can then be deleted.
7. **Resume:** on app open, any book with pending chunks shows "Continuar
   conversão".

### Data model (IndexedDB)

- `books`: id, title, createdAt, voice, status, chapters[{ id, title,
  textLength, status, durationSec }], position { chapterId, timeSec },
  speed.
- `chunks`: bookId, chapterId, index, text, status, mp3 (Blob).
- `chapterAudio`: bookId, chapterId, mp3 (Blob).
- `chapterText`: bookId, chapterId, cleanedText — **kept permanently**
  (small) so a book can be re-converted if audio is lost, without the PDF.
- `usage`: month (YYYY-MM), tier, charsSent.
- `settings`: apiKey, voiceName, defaultSpeed.

The original PDF is not kept after extraction. Builder's call: if iOS clears
the audio but the text survives, the book shows "Áudio removido —
reconverter" (subject to the free-tier guard). If all storage is cleared,
the owner re-imports the PDF; the exported MP3s in Files are the durable
backup. No separate backup/restore feature in v1.

### Playback

Single `<audio>` element fed by an object URL of the chapter blob. Media
Session metadata (title, chapter) and handlers (play, pause, seek ±30 s,
next/previous chapter). Save position every few seconds and on pause/
visibilitychange. Auto-advance to the next chapter. `playbackRate` for speed
(with `preservesPitch`).
